# bootstrap — 손으로 하는 구간

GitOps(ArgoCD)가 넘겨받을 수 있는 상태까지를 사람이 만든다. 플랫폼마다 폴더가 갈린다.

| 폴더 | 무엇을 | 손으로 하는 것 |
|---|---|---|
| [`k3s/`](k3s/README.md) | 빈 노드에서 허브(ArgoCD)가 서기까지 | 9단계 — CNI · 네임스페이스 · 스토리지 · 인증서 · 봉인 · CRD · 오퍼레이터 · ArgoCD |
| [`eks/`](eks/README.md) | 빈 EKS 를 허브에 붙이기까지 | 둘 — 허브에 등록 · Secret |

---

## 크기가 다른 이유 — 닭-달걀은 허브에만 있다

GitOps 를 시작하려면 ArgoCD 가 있어야 하고, ArgoCD 를 설치할 주체는 ArgoCD 가 될 수 없다.
그래서 허브가 서는 클러스터(k3s)는 CNI · CRD · 오퍼레이터 · ArgoCD 까지 손으로 깐다.

허브가 이미 떠 있는 클러스터에는 그 문제가 없다. EKS 에서 손으로 해야만 하는 것은 둘로 준다.

```
허브에 등록     허브가 아직 닿지 못하는 클러스터를 허브가 스스로 등록할 수는 없다
Secret        git 에 넣지 않기로 했다 — 봉인은 그 클러스터의 개인키에 묶여 미리 만들 수 없고,
              하루 살고 지우는 환경이라 git 에 남길 이유도 약하다
```

네임스페이스 · CRD · 오퍼레이터 · StorageClass 는 허브가 Application 으로 배달한다.
이 폴더의 크기가 곧 **플랫폼마다 GitOps 밖에 남는 수작업의 양**이다.

---

## 왜 환경(dev/stg)이 아니라 플랫폼(k3s/eks)으로 가르나

부트스트랩 절차를 정하는 것은 환경이 아니라 플랫폼이다 — CNI · 스토리지 · 제어면 접근이
플랫폼마다 다르다. 환경이 갈리는 자리는 `envs/<환경>/` 하나로 두기로 했고
([docs/구조-기준.md](../docs/구조-기준.md) 8절), 이 폴더는 그 규칙을 건드리지 않는다.
prd 도 EKS 면 `eks/` 를 그대로 쓴다.

## root-app 은 엄밀히 k3s 의 것이 아니다

`k3s/root-app.*` 은 허브(ArgoCD)의 부트스트랩이다. 허브가 지금 k3s 위에 있어서 `k3s/` 에 두었다.
허브를 다른 클러스터로 떼게 되면 그때 셋째 갈래(`hub/`)가 생긴다.
