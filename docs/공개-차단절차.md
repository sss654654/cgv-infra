# 공개 차단 절차

서비스를 인터넷에 공개한 뒤 문제가 생겼을 때 닫는 방법. 급할 때 읽는 문서라 판단은 빼고 명령만 둔다.

**위에서부터 시도한다.** 아래로 갈수록 영향 범위가 크다.

---

## 1. 밖에서 들어오는 길을 끊는다 — 가장 빠르고 되돌리기 쉽다

공유기 관리 화면에서 **443 포트포워딩을 끈다.** 이것만으로 인터넷에서 오는 모든 요청이 집에 도달하지 못한다.

```
바뀌는 것    인터넷에서 서비스가 안 열린다
그대로인 것   51820/UDP 터널은 살아 있어 관리 접근이 유지된다
             클러스터는 그대로 돌고, 집 안·터널에서는 서비스가 열린다
```

되돌리려면 포워딩을 다시 켠다. **원인을 모를 때는 이걸 먼저 한다** — 클러스터를 건드리지 않으므로 진단할 상태가 보존된다.

## 2. 이름을 내린다 — 캐시가 남아 즉시 끊기지 않는다

Cloudflare 대시보드에서 서비스 레코드를 지우거나 프록시를 끈다. DNS 캐시 때문에 이미 주소를 아는 쪽에는 한동안 계속 닿는다. 1번을 못 할 때만 쓴다.

## 3. 특정 서비스만 내린다

앱 하나에 문제가 있고 나머지는 살려야 할 때.

```bash
kubectl -n app scale deploy booking --replicas=0
kubectl -n app scale deploy queue   --replicas=0
kubectl -n app scale deploy frontend --replicas=0
```

**ArgoCD 가 되살린다.** `selfHeal: true` 라 몇 분 안에 선언된 값으로 돌아온다. 오래 내려 둬야 하면 자동 동기화를 먼저 끈다.

```bash
kubectl -n argocd patch app booking --type=merge -p '{"spec":{"syncPolicy":null}}'
```

되돌릴 때는 저장소의 값으로 다시 동기화한다.

```bash
kubectl -n argocd patch app booking --type=merge \
  -p '{"spec":{"syncPolicy":{"automated":{"prune":true,"selfHeal":true}}}}'
```

## 4. 직전 이미지로 되돌린다

새 배포 뒤에 문제가 생겼을 때. 이미지 태그는 `workloads/environments/dev/values-<앱>.yaml` 에 있고, argocd-image-updater 가 커밋한다.

```bash
git log --oneline -- workloads/environments/dev/values-booking.yaml
git revert <그 커밋>
git push
```

**클러스터에서 직접 이미지를 바꾸지 않는다.** 저장소가 정본이라 `selfHeal` 이 되돌린다. 되돌리는 것도 커밋으로 한다.

## 5. 데모 데이터를 비운다

좌석이 차거나 대기열이 꼬였을 때. CronJob(`demo-reset`)이 3시간마다 하는 일을 지금 한 번 돌린다.

```bash
kubectl -n app create job --from=cronjob/demo-reset reset-now
kubectl -n app logs job/reset-now
```

```bash
kubectl -n app get pods

```
